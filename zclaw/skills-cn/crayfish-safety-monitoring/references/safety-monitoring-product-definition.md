# 安全行为监测 Skill — 产品定义文档

> 小龙虾AI智能盒子 · 工业制造场景核心技能
> 版本：v1.0 | 日期：2026-06-23

---

## 一、一句话定义

**安全行为监测**是一个运行在小龙虾AI盒子（Pro版推荐）上的边缘AI视觉技能，通过对接工厂现有监控摄像头，实时检测工人安全行为合规（安全帽、区域越界、跌倒等），自动告警并生成安全报告，让中小工厂**不靠人盯人也能管好安全生产**。

---

## 二、解决的核心痛点

| 痛点 | 具体表现 | 影响 |
|------|----------|------|
| 人工巡查覆盖不全 | 安全员一天巡2-3次，每次也就十几分钟，大部分时间是盲区 | 事故隐患发现不及时 |
| 违规行为难溯源 | 出了事故翻监控找原因，几小时的录像翻到崩溃 | 责任认定困难 |
| 安全员招人难留人难 | 安全监管岗枯燥、责任大，年轻人不愿意干 | 人员流动率高 |
| 政策合规压力大 | 《安全生产法》要求企业建立双重预防机制，执法越来越严 | 违规处罚、停工整顿风险 |
| 中小工厂预算有限 | 大厂安全方案几万到十几万，小微工厂根本买不起 | 安全生产投入不足 |

**关键数据**：我国制造业年均因人员违规操作导致的直接经济损失超 **320亿元**（《2026年中国制造业安全生产白皮书》）。

|--------|------|----------|---------|-----------|
| 🪖 **安全帽佩戴** | 检测进入生产区域的人员是否佩戴安全帽 | 车间、仓库、建筑工地 | ⭐⭐ | **P0 必做** |

| 🚬 **吸烟检测** | 检测禁烟区吸烟行为 | 仓库、加油站、化工厂 | ⭐⭐ | P1（特定行业刚需） |
| 🏃 **奔跑/打闹检测** | 检测工作区域异常跑动行为 | 仓储物流、生产线 | ⭐⭐⭐ | P2 |
| 👥 **区域人数统计** | 统计指定区域人数，超限告警 | 受限空间、消防管控 | ⭐⭐ | P2 |

### 3.2 第一期（MVP）能力范围

**只做3项**，覆盖80%的安全生产需求：
1. **安全帽佩戴检测** — 最大刚需，政策红线
2. **区域越界检测** — 防机械伤害的核心能力
3. **跌倒检测** — 关乎生命安全，预防二次伤害

## 四、工作原理

```
工厂监控摄像头 → 小龙虾AI盒子(Pro) → 本地多模型并行推理 →
  ├─ 全部合规：无事发生（数据不出盒）
  ├─ 未戴安全帽 → 抓拍+标注 → 推送至安全员微信/现场声光告警
  ├─ 越界进入 → 抓拍+标注 → 推送告警
  └─ 人员跌倒 → 抓拍+标注 → 紧急告警（升级通知）
```

**技术实现要点**：

| 环节 | 方案 | 说明 |
|------|------|------|
| 检测策略 | 多模型并行推理（每类检测一个轻量模型） | Pro版16-24TOPS算力足够同时跑3-4个模型 |
| 告警防抖 | 连续3帧以上检测到违规才触发告警 | 减少误报（避免弯腰系鞋带误判为跌倒） |
| 现场联动 | 支持GPIO外接声光报警器 | 即时制止违规行为 |
| 推送渠道 | 企业微信 / 微信 / 钉钉 / 短信 | 告警分级：普通 → 微信，紧急 → 电话+短信 |
| 证据留存 | 告警截图+前后5秒短视频本地存储 | 可追溯、可定责 |
| 报告看板 | OpenClaw平台安全看板 | 日/周/月违规统计、趋势分析、合规率 |

**离线能力**：网络中断时，本地模型持续检测+缓存告警，恢复后推送。声光报警器本地直连，不依赖网络。

## 五、用户使用流程

### Step 1：开机绑定
盒子通电 → 手机扫码绑定 → 选择「安全行为监测」Skill → 点击启用

### Step 2：摄像头配置
- 对接现有工厂监控（RTSP协议）
- Pro版最多接 **4路** 画面
- 在OpenClaw上框选检测区域 + 设置检测规则

### Step 3：规则设置（30秒完成）
```
┌─ 安全帽检测：开启 ✅
│   ├─ 告警方式：微信推送 + 现场声光
│   └─ 生效时间：07:00-19:00（白班时段）
├─ 区域越界：开启 ✅
│   ├─ 危险区域：画框标注（机械臂区）
│   └─ 告警方式：微信推送
└─ 跌倒检测：开启 ✅
    └─ 告警方式：微信推送 + 短信（紧急）
```

### Step 4：自动运行
- AI 7×24小时不间断检测
- 零人工干预，零误报困扰

### Step 5：查看报告
- 每日安全报告：今日违规次数、合规率、趋势对比
- 每周安全简报：环比变化、重点问题区域
- 可导出为安全检查台账

## 九、技术实现路径

### Phase 1：MVP（6-8周）
- 安全帽检测模型训练（基于YOLOv8-nano/s）
- 区域越界检测（结合目标检测+区域ROI逻辑）
- 跌倒检测模型（基于姿态估计或检测+跟踪）
- Pro版盒子上跑通3模型并行推理
- 微信/企业微信告警推送
- 基础声光报警联动

### Phase 2：产品化（4-6周）
- OpenClaw配置界面（规则设置、区域画框、告警开关）
- 告警去重与防抖机制
- 日/周安全报告自动生成
- 历史违规记录检索

### Phase 3：扩展（持续）
- 模型蒸馏优化，延迟降至 < 100ms/帧
- 更多检测项：防护服、吸烟、人数超限
- 多盒子统一管理看板
- 与灵虾平台的安全数据上报对接

## 十、关键风险与应对

| 风险 | 应对 |
|------|------|
| 工厂环境复杂（光照、遮挡、角度）导致误检高 | MVP阶段限定标准场景（室内车间、固定摄像头位），逐步积累数据优化 |
| 安全帽款式多样（颜色、形状不同） | 训练数据覆盖主流颜色（红/黄/白/蓝）和常见款式，持续收集边缘案例 |
| 客户期望过高（期望100%准确） | 明确定位为"辅助监测工具"，告警需要人工二次确认，不是执法工具 |
| 中小工厂安全意识薄弱，付费意愿低 | 用"省一个安全员的工资"算账，政策合规压力作为第二推动力 |
