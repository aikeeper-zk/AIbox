#### 现象描述

**客户原话**：
> "{客户原文，如'我们摆放促销牌的时候，AI就乱告警，店员被烦死了'}"

**复现步骤**：
1. 在货架区域放置"双11特惠"促销牌（黄色A4纸）
2. AI在30秒内连续触发空位告警3-5次
3. 人工移除促销牌后1分钟内恢复正常

**期望行为**：
> {如"促销牌属于营销道具，AI应该识别为'非空位'，不应触发告警"}

**实际行为**：
> {如"AI将促销牌识别为空位，连续触发P2中级别告警，影响店员正常工作"}

#### 根因分析（5-Why法）

```
问题：促销牌遮挡货架时，AI误判为空位
Why 1: AI为什么将促销牌识别为货架空位？
        → 因为促销牌的黄色与空位颜色接近
Why 2: 黄色与空位颜色为什么接近？
        → 模型训练时未包含"非典型遮挡物"的负样本
Why 3: 为什么未包含这类负样本？
        → 训练数据集主要来自常规货架，未覆盖促销场景
Why 4: 为什么训练数据未覆盖促销场景？
        → 因为多数门店不使用促销牌
Why 5: 根本原因是什么？
        → 模型未具备"动态上下文感知"能力 + 缺乏促销道具白名单机制
```

#### 解决方案

**临时方案（即时缓解）**：
- 推送配置项：允许客户在"排期日历"中标记促销日，系统自动放宽空位阈值30%
- 客户提供促销牌白名单图片，AI添加到误报过滤库

**永久方案（彻底解决）**：
- 模型侧：增加"常见遮挡物"负样本训练集（促销牌/POP广告/价签）
- 产品侧：增加"促销模式"开关，启用专门的算法分支
- 数据侧：标记所有促销期间的告警，人工复核后回流到训练集

**预防措施**：
- 在Skill上线前增加"常见遮挡物场景"测试用例
- 在客户巡检时主动询问"是否使用促销道具"
- 每季度收集一次误报样本，主动学习

#### 客户原始需求描述

**客户原话**：
> "我们超市经常摆促销牌，但每次摆上去AI就乱报。希望能在系统里加一个'促销牌白名单'，让我们提前告诉AI'这些是正常的道具，不需要告警'。最好还能设置'促销模式'，一键关闭空位告警半天。"

**使用场景**：
1. 节假日前，门店需要摆放大量促销道具
2. 促销活动期间不期望收到"空位告警"（因为顾客在挑选时需要翻看商品）
3. 促销结束后，恢复正常空位检测

**期望功能**：
- 在告警规则中增加"促销日期历"，自动切换告警阈值
- 在系统中上传"促销道具"图片库，作为负样本
- 一键启用/关闭"促销模式"

#### FDE的洞察（产品可参考）

**隐性需求挖掘**：
- 表面需求：减少误报
- 深层需求：促销活动期间AI不要打扰门店正常运营
- 关联需求：未来可衍生"季节性营销"Skill（如"双11模式"、"春节模式"）

**实现建议**：
- 与现有"商品学习"功能复用（负样本管理可统一）
- 与"日历模式"功能结合（节假日阈值调整机制）
- 可作为"零售场景增强"包单独定价

**预估开发量**：
- 复杂度：中（需涉及模型+前端+接口）
- 人力：前端1人/2周 + 算法1人/2周 + 测试1人/1周
- 复用率：60%（与商品学习的负样本管理可共用）

#### 场景描述

**客户实际痛点**：
> "我们是连锁餐饮品牌，120家门店，食品安全局每年检查卫生。厨师不戴口罩、头发外露、操作台有异物这些问题经常被点名。我们想用AI自动检测这些违规，让顾客能看到'后厨直播+AI保障'。"

**现有解决方案不足**：
- 传统监控无法自动识别违规
- 食品安全局检查前才紧急整治，缺乏常态化监督
- 顾客看不到后厨，不信任感强

**期望AI能力**：
- 口罩/帽子/手套检测（复用现有Skill）
- 操作台异物检测（新增功能）
- 后厨直播流中自动叠加违规标签
- 违规事件推送给店长手机+看板

#### FDE的初步可行性判断

**可复用Skill**：
- ✅ 口罩检测 → 复用安全帽检测模型（迁移学习）
- ✅ 工服检测 → 复用安全服检测模型
- ✅ 实时直播流处理 → 复用客流统计流处理逻辑

**需新增能力**：
- ❓ 操作台异物检测（食品残渣/头发/纸屑）→ 算法工程新方向
- ❓ 直播流叠加标签（OBS/直播SDK集成）→ 需视频技术团队

**商业潜力**：
- 客户数量：中国连锁餐饮50万+（保守估计有需求的5%）
- 单店报价：Pro盒子¥16,999 + 摄像头5路¥500×5 = 盒+外设¥19,499
- 总市场：约¥50亿硬件市场 + 持续SaaS订阅

**风险评估**：
- 数据合规：餐饮业摄像头对员工有合规要求，需协助算法备案
- 准确性：异物检测（如头发 vs 菜叶）易混淆
- 行业经验：智体共合在餐饮业无积累，需从零开始

> FDE作为前线人员，掌握了大量客户真实心声。本节是FDE对产品团队的"内部信"，未被客户明确说但应该被听到的声音。

**产品需关注的"未说出口"声音**：

1. **客户希望"零干预自动化"**：
   - 现在每次新增SKU需要手动标注+训练，能不能做"开箱即用"模式？
   - 现在的算法需要"7天冷启动期"，对客户体验是负担

2. **客户希望"少看屏幕"**：
   - 现在的告警看板需要一直挂着显示，能不能做语音播报/物理按钮？
   - 老板们不喜欢每天刷App，希望"AI主动汇报"

3. **客户希望"看到效果"**：
   - 现在客户很难看到ROI数据，希望有自动生成的"月度效果报告"
   - 客户希望对外展示"我们用了AI"，需要可分享的截图物料

4. **客户希望"少出钱多办事"**：
   - 希望打通龙虾U盘+盒子的算力池，按需调用不同硬件
   - 希望SaaS订阅可以"按Skill计费"而非"按盒子计费"

5. **客户希望"不被锁死"**：
   - 数据导出是否有标准格式？数据迁移是否方便？
   - 算法备案是否支持客户自定义？

**这些声音应该被产品团队看到**：

```
建议FDE每月提交1份"产品情报笔记"（内部文件）汇总：
- 客户口头抱怨但未提需求的内容
- 客户环境的"补丁"（临时方案的真痛点）
- FDE与不同角色沟通时听到的不同声音
- 行业展会/竞争对手动态中听到的客户想法
```

## 15. 模板使用指引（给FDE）

### 15.1 反馈收集四节奏

```
┌─ 实时（现场/客服）
│   └─→ 异常告警/紧急问题，立刻进入 Bug类 流程
│
├─ 每周（月度运维时）
│   └─→ 从巡检+客户沟通中收集功能/场景反馈
│
├─ 每月（反馈报告）
│   └─→ 整合到月度反馈报告
│
└─ 每季度（深度复盘）
    └─→ 战略类反馈+案例库评估
```

### 15.2 反馈收集的标准动作

**每次客户现场**：
- 收集至少3条反馈（赞/吐槽/建议）
- 拍摄现场照片（脱敏）
- 复述给客户确认理解一致
- 24小时内录入CRM

**每次月度运维**：
- 回顾本月所有客户沟通
- 整理反馈报告初稿
- 提交产品/技术/商务团队

**每个季度/项目结束**：
- 深度复盘
- 评估案例价值
- 提交管理层

### 15.3 反馈的"价值密度"评估

| 反馈密度 | 价值 | 后续 |
|---------|------|------|
| **高价值反馈**：能转化为产品功能/新场景/新销售 | 高 | 立即推动立项 |
| **中等价值反馈**：能优化体验但价值有限 | 中 | 进入需求池 |
| **低价值反馈**：情绪类/不可量化 | 低 | 记录后归档 |
