# AI Agent工作流 Skill — 产品定义文档

> 小龙虾AI智能盒子 · 平台级核心技能
> 版本：v1.0 | 日期：2026-06-24

---

## 一、一句话定义

**AI Agent工作流**是运行在小龙虾AI盒子上的**零代码可视化自动化引擎**，让用户像搭积木一样，把AI检测、告警推送、设备联动、数据分析等能力拖拽成一条自动化流程——**"检测到A→触发B→执行C→通知D"**，不需要写一行代码。

---

## 二、解决了什么根本问题

### 2.1 用户的真实困境

小龙虾AI盒子有多个Skill（货架空位检测、安全行为监测、客流分析等），每个Skill都是独立运行的。但当用户想把多个能力**串起来**时，就遇到了瓶颈：

| 场景 | 用户的理想 | 没有工作流时的现实 |
|------|-----------|------------------|
| 安全监测+声光报警+微信通知 | "检测到没戴安全帽→灯闪→拍个照→发到安全群" | 3个功能各自独立，要手动拼凑 |
| 缺货检测+补货建议+推送老板 | "检测到货架空→AI生成补货建议→推给老板确认" | 只能单独看空位，补货建议还得另开APP |
| 客流低峰+自动切换节能模式 | "连续30分钟没人→自动关灯关空调→有人来再开" | 做不到自动联动 |

### 2.2 核心价值

> **让小龙虾AI盒子从一个"工具包"变成"自动化管家"**

用户不需要理解"AI模型""API调用""条件分支"这些技术概念，只需要想清楚**"如果……就……"**的逻辑即可。

## 三、核心能力

### 3.1 可视化工作流编辑器（OpenClaw平台）

用户可以在OpenClaw网页上，通过拖拽方式编排自动化流程。

**三种基础节点类型**：

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  🎯 触发器   │ ──→ │  ⚙️ 执行器  │ ──→ │  📤 输出器  │
│              │     │             │     │             │
│ 什么事件启动  │     │ 要做什么操作 │     │ 通知谁/存哪里│
└─────────────┘     └─────────────┘     └─────────────┘
```

**触发器节点（Trigger）**：

| 触发器 | 说明 | 可配置参数 |
|--------|------|-----------|
| AI检测触发 | 某个Skill检测到特定事件 | 选择Skill、选择检测项、置信度阈值 |
| 时间触发 | 按固定时间/周期执行 | 时间、星期、重复间隔 |
| 设备触发 | 外接传感器信号启动 | GPIO电平变化、串口数据 |
| 手动触发 | 按钮一键启动流程 | 微信小程序/OpenClaw面板 |

**执行器节点（Action）**：

| 执行器 | 说明 | 参数 |
|--------|------|------|
| AI分析 | 调用云端大模型分析结果 | 选择模型、输入提示词 |
| 本地模型 | 执行本地模型推理 | 选择已部署模型 |
| 声光告警 | 控制本地声光报警器 | 闪烁模式、持续时间 |
| GPIO控制 | 控制继电器等外设 | 引脚号、输出电平 |
| 数据记录 | 写入本地日志/数据库 | 记录字段、标签 |
| 延迟等待 | 等待指定时间后继续 | 秒/分/时 |
| 条件分支 | If-Then-Else逻辑 | 判断条件 |

**输出器节点（Output）**：

| 输出器 | 说明 | 参数 |
|--------|------|------|
| 微信推送 | 推送到指定联系人/群 | 接收人、消息模板 |
| 企业微信/钉钉 | 推送到企业IM | Webhook地址 |
| 短信告警 | 紧急告警短信发送 | 手机号（需套餐支持） |
| 邮件报告 | 发送报表/截图 | 邮箱地址 |
| 现场语音播报 | 外接音箱语音提醒 | 播报文本（TTS） |

### 3.2 预设模板（开箱即用）

用户可以直接使用预设模板，无需从零搭建：

| 模板名称 | 工作流内容 | 适用场景 |
|----------|-----------|----------|
| 🪖 **安全应急响应** | 检测到违规→声光报警→拍照→微信推送安全群→记录日志 | 工厂安全 |
| 📦 **智能补货提醒** | 检测到空位→AI生成补货清单→推送给老板→记录缺货数据 | 零售 |
| 🧍 **跌倒紧急救助** | 检测到跌倒→等待10秒确认→声光告警→短信通知紧急联系人→记录 | 社区/养老 |
| 🚗 **夜间防盗模式** | 23:00-6:00检测到移动→本地录像→微信告警→声光驱离 | 店铺夜间安防 |
| 📊 **每日运营报告** | 每日22:00→汇总当天客流/缺货/告警数据→AI生成总结→推送到老板微信 | 综合运营 |

### 3.3 工作流运行模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 实时模式 | 事件触发立即执行 | 安全告警、防盗 |
| 定时模式 | 按预设时间周期执行 | 日报生成、设备自检 |
| 条件模式 | 满足条件才执行分支 | 分级告警（普通vs紧急） |
| 批处理模式 | 攒够一批触发条件后统一处理 | 能耗优化 |

## 四、关键技术架构

### 4.1 架构分层

```
┌──────────────────────────────────────┐
│         OpenClaw 云端平台             │
│  ┌──────────────────────────────┐    │
│  │  可视化工作流编辑器 (Web IDE) │    │
│  │  - 拖拽画布                   │    │
│  │  - 节点配置面板               │    │
│  │  - 模板市场                   │    │
│  └──────────┬───────────────────┘    │
│             ↓ 工作流定义 (JSON)        │
│  ┌──────────┴───────────────────┐    │
│  │  工作流版本管理与同步服务      │    │
│  └──────────┬───────────────────┘    │
└─────────────┼────────────────────────┘
              ↓ OTA同步
┌─────────────┼────────────────────────┐
│  小龙虾AI盒子 (边缘端)               │
│  ┌──────────┴───────────────────┐    │
│  │  工作流执行引擎 (本地运行)     │    │
│  │  - 事件监听器                 │    │
│  │  - 节点调度器                 │    │
│  │  - 状态管理器                 │    │
│  └──────────────────────────────┘    │
│  ┌──────────┬──────────┬─────────┐   │
│  │ 触发器池 │ 执行器池  │ 输出器池 │   │
│  └──────────┴──────────┴─────────┘   │
└──────────────────────────────────────┘
```

### 4.2 边缘端工作流引擎

- **事件驱动架构**：所有触发器注册到事件总线，事件发生→匹配工作流→执行
- **轻量级**：C++/Rust实现的运行时，内存占用 < 50MB
- **离线运行**：工作流定义在离线前同步到盒子，断网后完全本地执行
- **状态持久化**：工作流执行状态写入本地SQLite，断电恢复后继续
- **资源隔离**：每个工作流有独立的资源配额（CPU/内存/磁盘），一个工作流崩溃不影响其他

### 4.3 性能指标

| 指标 | 目标值 |
|------|--------|
| 单盒子支持工作流数量 | ≥ 20个 |
| 单工作流节点数上限 | ≥ 30个 |
| 节点间传输延迟 | < 10ms（本地） |
| 工作流启动时间 | < 500ms |
| 工作流编辑→同步生效 | < 5秒 |
| 运行时内存开销 | < 50MB（基础）+ 按需 |

## 五、用户使用流程

### Step 1：打开工作台
登录OpenClaw平台 → 进入「AI Agent工作流」 → 看到一个空白画布

### Step 2：搭积木
- 从左侧拖一个「AI检测触发」到画布
- 选择「安全行为监测→未戴安全帽」
- 拖一个「声光告警」连接上去
- 再拖一个「微信推送」→ 输入"老板，有人没戴安全帽！"
- 再拖一个「数据记录」→ 记录本次事件

### Step 3：一键启用
点击「保存并启用」 → 工作流自动同步到盒子 → 开始运行

### Step 4：查看运行记录
在OpenClaw上可以看到每次工作流的执行日志、执行时间、成功/失败状态

## 六、差异化竞争力

### 与市面方案对比

| 对比维度 | 公有云Agent平台（OpenAI Agent Studio等） | 传统IoT规则引擎（Node-RED等） | 小龙虾AI Agent工作流 |
|----------|--------------------------------------|--------------------------|-------------------|
| 运行位置 | 云端 | 本地/服务器 | **边缘盒子本地运行** |
| AI能力集成 | 调用云端大模型 | 无原生AI支持 | **原生集成所有盒子AI Skill** |
| 部署复杂度 | 需要云账号、API Key | 需要配置运行环境 | **开盒即用，扫码启用** |
| 离线能力 | 断网不可用 | 本地可运行 | **完全离线运行** |
| 目标用户 | 开发者/技术团队 | 有一定技术的开发者 | **零技术背景的终端用户** |
| 成本 | API按量计费，成本不可控 | 免费开源，但需自己维护 | **SaaS订阅全包含，成本可控** |
| 设备联动 | 纯软件 | GPIO等硬件接口 | **既是软件工作流也是硬件联动** |

**一句话差异化**：这是唯一一个**在边缘AI盒子上本地运行**的零代码工作流引擎，AI检测→设备联动→消息推送全链路在一个盒子里闭环，不依赖云端、不需要写代码。

## 七、商业模式建议

### 方案A：SaaS升级增值服务（推荐）

- **基础SaaS（¥299/月）**：可以使用预设模板，最多同时运行5个工作流
- **高级SaaS（¥499/月）**：自有编排+无限工作流+历史数据导出
- **企业SaaS（¥999/月）**：多盒子统一管理+跨盒子联动+专属模板开发

### 方案B：平台核心能力，免费标配

- AI Agent工作流作为OpenClaw平台的基础能力，所有SaaS用户都可以使用
- 通过降低使用门槛→提高用户粘性→降低流失率
- 靠生态黏性赚钱，不是靠这个功能直接收费

> **建议用方案A的轻量版**，预设模板免费，让用户体验到价值；进阶编排能力作为SaaS升级的付费点。

## 八、技术实现路径

### Phase 1：引擎核心（4-6周）
- 工作流执行引擎开发（基于事件总线的节点调度）
- 触发器池：AI检测触发 + 时间触发
- 执行器池：声光告警 + GPIO控制 + 数据记录
- 输出器池：微信推送 + 本地日志
- 工作流定义JSON Schema设计

### Phase 2：OpenClaw编辑界面（4-6周）
- 可视化拖拽编辑器（基于React Flow / Vue Flow等开源方案）
- 节点配置面板
- 工作流向盒子同步（OTA）
- 运行日志查看

### Phase 3：模板与生态（4-6周）
- 预设模板：安全应急、智能补货、跌倒救助等
- 条件分支节点
- 云端大模型调用执行器（调用混合智能网关）
- 工作流导入/导出/分享

### Phase 4：高级能力（持续）
- 跨盒子联动工作流（A盒子检测→B盒子联动）
- 工作流模板市场（用户可上传/下载模板）
- 工作流性能监控与告警
- 版本回滚

## 九、关键风险与应对

| 风险 | 应对 |
|------|------|
| 可视化编辑器开发成本高 | Phase 2使用开源方案（React Flow等）快速搭建MVP，不做大而全 |
| 边缘端资源有限，复杂工作流跑不动 | 设置工作流资源配额上限，超出自动提示优化建议 |
| 用户编排出逻辑死循环 | 引擎内置循环检测，超过10层嵌套自动终止并告警 |
| 用户期望过高（想编排任意AI模型） | 初期限定只能使用盒子已有的Skill和预设执行器，后续逐步开放 |
| 与通用平台比功能不够丰富 | 定位清晰：不做通用工作流，只做"AI检测→设备联动→消息通知"的闭环 |

## 十、这个Skill的独特战略价值

**前面两个Skill（货架空位检测、安全行为监测）是"功能"——让盒子能干活。**

**AI Agent工作流是"平台"——让盒子能自己长出新能力。**

| 对比 | 没有工作流 | 有了工作流 |
|------|-----------|-----------|
| 用户使用方式 | 用单个Skill，各干各的 | 把多个Skill串成自动化流程 |
| 场景覆盖 | 固定场景 | **用户自定义场景，无限可能** |
| 竞品模仿难度 | 中（做个检测模型不难） | **高（需要完整的边缘端编排引擎）** |
| 平台粘性 | 低（用坏了换一家） | **高（工作流跑在上面，迁移成本高）** |
| 生态想象力 | 卖硬件+功能 | **模板市场+开发者生态+插件分成** |

**结论：这是小龙虾AI盒子从"智能硬件"变成"智能平台"的关键一跃。**
