## 一、AI产品评估清单

在启动AI产品设计前，用以下清单评估可行性：

### 场景适配性评估

| 评估维度 | 适合AI ✅ | 不适合AI ❌ |
|---|---|---|
| 数据基础 | 有大量历史数据或可获取训练数据 | 数据极少或获取成本极高 |
| 任务性质 | 模式识别、个性化推荐、内容生成 | 100%确定性要求、零容错 |
| 规则复杂度 | 规则难以穷举，需要"理解" | 规则清晰固定，传统逻辑即可 |
| 容错空间 | 用户可容忍一定误差 | 误差代价极高（如医疗诊断、法律判决） |
| 价值密度 | 人工处理成本高，AI可大幅提效 | 人工已足够高效 |

### 技术可行性评估

- [ ] 是否有可用的基础模型（开源/商用API）？
- [ ] 模型能力是否覆盖核心任务？（先做PoC验证）
- [ ] 数据合规性是否满足要求？（数据是否可出境、是否含敏感信息）
- [ ] 推理成本是否在商业模式可接受范围内？
- [ ] 延迟要求是否可满足？（实时 vs 离线）

### 商业可行性评估

- [ ] 用户是否愿意为AI能力付费？付费意愿有多强？
- [ ] AI带来的效率提升是否可量化？
- [ ] 竞品是否已有类似AI功能？差异化在哪？
- [ ] AI功能的边际成本是否随规模下降？

## 二、Prompt工程指南（产品经理视角）

Prompt是AI产品的"配置文件"，产品经理需要从产品视角理解和设计Prompt。

### Prompt设计原则

1. **角色定义**：明确AI扮演什么角色（"你是一个专业的客服助手"）
2. **任务描述**：清晰定义要做什么，而非怎么做
3. **约束条件**：明确边界——不应该做什么、格式要求、长度限制
4. **示例提供**：给出2-3个期望的输入/输出示例（Few-shot）
5. **异常处理**：定义AI无法回答时的兜底策略

### Prompt模板示例

```
## 角色
你是一个{行业}领域的专业{角色}，帮助用户{核心任务}。

## 任务
根据用户输入的{输入描述}，生成{输出描述}。

## 要求
- 输出格式：{格式要求}
- 语言风格：{风格要求}
- 长度限制：{字数/段落数}
- 不允许：{禁止事项}

## 示例
用户输入：{示例输入1}
AI输出：{示例输出1}

用户输入：{示例输入2}
AI输出：{示例输出2}

## 用户输入
{用户实际输入}
```

### Prompt版本管理

- 每次修改Prompt都记录版本号、修改原因、效果对比
- 维护Prompt回归测试集：10-20个典型case + 5-10个边界case
- 模型升级后必须回归测试，确认Prompt效果未退化

## 三、大模型应用架构模式

### 常见架构模式

| 模式 | 说明 | 适用场景 |
|---|---|---|
| **纯Prompt** | 直接调用大模型API | 简单问答、内容生成 |
| **RAG** | 检索增强生成：先检索相关知识，再让模型基于检索结果生成 | 知识库问答、客服、文档查询 |
| **Agent** | 大模型自主调用工具，多步推理 | 复杂任务（数据分析、代码生成、工作流编排） |
| **微调** | 在领域数据上微调基础模型 | 需要深度领域适配、风格统一 |
| **混合** | RAG + Agent + 微调组合 | 企业级AI应用 |

### 产品经理需要关注的架构决策

1. **选择哪种模式**：从简单开始（纯Prompt），验证价值后再升级架构
2. **RAG的知识库质量**：垃圾进垃圾出，知识库的整理质量决定效果上限
3. **Agent的工具设计**：工具定义是否清晰、参数是否简洁、错误处理是否完善
4. **微调的数据**：数据质量 > 数据量，1000条高质量数据胜过10000条噪声数据
5. **成本控制**：Token消耗、推理延迟、并发能力——这些直接影响商业模式

## 四、AI产品效果评估体系

### 评估指标分层

**第一层：模型能力指标**（技术团队主导）
- 准确率 / 召回率 / F1
- 幻觉率（生成内容与事实不符的比例）
- 一致性（相同输入多次输出的稳定性）

**第二层：产品体验指标**（产品团队主导）
- 采纳率：用户直接使用AI输出的比例
- 修正率：用户修改AI输出后使用的比例
- 满意度：用户对AI输出的主观评分
- 首次成功率：一次生成即满足需求的比例

**第三层：业务价值指标**（业务团队主导）
- 效率提升：AI辅助 vs 纯人工的效率对比
- 成本节约：人力成本降低、运营成本降低
- 收入增长：AI功能带来的新增收入/转化率提升
- 用户留存：AI功能对用户留存的影响

### A/B测试设计要点

- **对照组**：无AI辅助 vs 有AI辅助（而非不同AI方案对比）
- **测试周期**：至少2周，覆盖完整工作周期
- **样本量**：确保统计显著性（p < 0.05）
- **霍桑效应**：用户知道在测试可能行为变化，需排除

## 五、AI产品安全与合规

### 数据安全

- 用户数据是否脱敏后再送入模型？
- 数据是否本地处理？（边缘部署 vs 云端调用）
- 数据留存策略：输入是否被用于模型训练？用户是否知情同意？

### 内容安全

- 生成内容是否经过审核？
- 是否有敏感词/有害内容过滤？
- 用户举报和反馈机制是否完善？

### 合规要求

- **中国**：《生成式人工智能服务管理暂行办法》《数据安全法》《个人信息保护法》
- **跨境**：数据出境需通过安全评估
- **行业特殊要求**：金融、医疗、教育等行业有额外的AI应用合规要求

### 偏见与公平性

- 模型输出是否存在性别/种族/地域偏见？
- 是否对特定群体存在系统性不公平？
- 是否有定期审计和纠正机制？

## 六、AI产品设计Checklist

在交付AI产品设计方案前，逐项确认：

### 场景与需求
- [ ] 明确了AI要解决的核心问题
- [ ] 验证了场景适合用AI（而非传统方案）
- [ ] 定义了清晰的成功标准

### 交互设计
- [ ] 选择了合适的人机协作模式
- [ ] 设计了AI输出的人工审核/修正流程
- [ ] 处理了AI无法回答时的兜底策略
- [ ] 考虑了延迟体验（加载态、流式输出、排队机制）

### 效果与质量
- [ ] 定义了三层评估指标（模型能力/产品体验/业务价值）
- [ ] 设计了A/B测试方案
- [ ] 准备了Prompt回归测试集
- [ ] 定义了效果达标阈值和下线标准

### 安全合规
- [ ] 数据脱敏方案已确认
- [ ] 内容审核机制已设计
- [ ] 合规要求已梳理并满足
- [ ] 偏见风险已评估

### 商业模式
- [ ] AI成本（Token/推理/存储）已估算
- [ ] 收费模式已设计（按量/订阅/增值）
- [ ] ROI模型已搭建
