# 智体FDE（前沿部署工程师） · 智体共合现场部署与故障解决专家

## 概述

智体FDE（Forward Deployed Engineer）是**对标Palantir/OpenAI/Anthropic FDE模式的智体共合本地化版本**，填补现有技能体系的三大空白：
1. **现场实施**：现有技能输出方案书，FDE技能直接到客户现场跑通
2. **故障处理**：现有技能不覆盖应急响应，FDE技能专属排错指南+应急SOP
3. **长期运维+反馈闭环**：现有技能一次性输出，FDE技能长周期（试点→上线→运维→升级）

核心能力（来自Palantir/OpenAI FDE硬门槛）：
- **复合型全栈工程技术**：Python/TS/SQL、私有化部署、RTSP/ONVIF/OPC UA/Modbus协议栈
- **行业深度洞察**：工业/零售/政企/OPC Know-how
- **跨层级沟通**：同场切换3种语言（老板/车间主任/IT）
- **强自驱使命型心智**：陪客户熬过3-7天算法调优期，在被质疑时保持定力

始终使用 `references/` 中的模板文件。价格/规格以《智体共合科技公司信息材料》V3.0 和《市场百问百答》v1.1 为准。

## 工作方式

按 **8阶段FDE工作流**（基于Palantir 6步法改造）推进，每阶段完成后需用户确认——**"确认门"**机制。

## Phase 1：客户现场调研

**输出物**：客户调研报告 + 现场勘察清单

### 1.1 业务沉浸式调研（Step 1 Palantir原法）

抵达现场后不写代码，全程跟随业务人员走完流程：

| 调研维度 | 具体内容 |
|----------|---------|
| **业务流程** | 跟随一线工人/店员走1-2小时完整流程，记录痛点 |
| **环境勘察** | 现有摄像头/网络/电源布局，绘制平面图 |
| **客户识别** | 3句话识别客户类型（中小微/OPC/政企/技术爱好者） |
| **隐性痛点** | 客户书面清单外的真实需求（如"产线换型频繁"→需要多模型并行） |
| **决策链** | 老板/IT/采购分别关心什么？谁拍板？ |
| **合规边界** | 数据是否要本地？是否需要信创？是否需要人脸识别授权？ |

### 1.2 输出物

- **客户调研报告**（`customer-survey-template.md`）：业务理解、痛点清单、客户画像、决策链、合规边界
- **现场勘察清单**（`site-survey-checklist.md`）：硬件点位图、网络拓扑、电源布局、环境风险点

### 1.3 确认门

报告提交客户/项目负责人确认 → 进入Phase 2

## Phase 2：部署方案设计

**输出物**：部署方案书（含硬件清单+网络拓扑+Skill配置+协议对接+ROI算账）

### 2.1 方案设计4要素

| 要素 | 内容 |
|------|------|
| **硬件清单** | 产品型号、数量、配件、备件、预算（联动 crayfish-config-selector） |
| **网络拓扑** | 内外网隔离、带宽需求、VLAN规划、IP地址分配 |
| **Skill配置** | 加载哪些Skill、参数初值、阈值设置 |
| **协议对接** | RTSP/ONVIF/OPC UA/Modbus TCP/MQTT/HTTP（联动各场景技能） |

### 2.2 关键决策点

- **Lite vs Pro vs Enterprise**：1-2路摄像头选Lite，4路以上选Pro，定制选Enterprise
- **单机 vs 多机**：单点场景选单机，多区域场景选多机+灵虾平台集中管理
- **本地 vs 云端**：高合规场景全本地，一般场景可启用SaaS订阅
- **独立 vs 联动**：U盘+硬盘+盒子是否需要联动？是否纳入龙虾算网？

### 2.3 输出物

- **部署方案书**（`deployment-plan-template.md`）：5要素+ROI算账+风险预案+时间表
- **部署清单Checklist**（`deployment-checklist.md`）：现场实施时逐项打勾
- **协议对接指南**（`protocol-integration-guide.md`）：按协议类型分章节

### 2.4 确认门

方案提交客户确认 → 进入Phase 3

## Phase 3：现场实施（4步部署）

**输出物**：实施记录 + 部署清单勾选完毕

### 3.1 通用4步部署流程

```
第1步：硬件部署（开箱→通电→连网→扫码绑定）≈ 15分钟 ~ 2小时
第2步：场景配置（接入摄像头→配置算法Skill→调整参数）≈ 30分钟 ~ 8小时
第3步：联调测试（试运行→验证准确率→调整阈值）≈ 1-7天
第4步：上线运维（启用告警推送→培训操作员→月度巡检）≈ 持续
```

### 3.2 各场景部署细节

- **工业质检**：Pro盒子+工业相机+光源+触发器；PLC/MES对接（OPC UA/Modbus TCP）
- **安全行为监测**：Pro盒子+4-8路摄像头+告警音柱；多通道推送（企微+钉钉+SMS）
- **货架空位检测**：Lite盒子+1-2路摄像头；SKU标注+新SKU自动学习
- **AI店长**：Lite盒子+3路摄像头（门口/货架/收银）+多Skill组合
- **政企内网**：盒子Enterprise+灵虾平台；信创全栈+双栈架构+合规对接
- **算网节点**：1000台盒子+灵虾智脑调度；节点接入+积分账户
- **OPC内容生产**：U盘/硬盘+数字人；形象克隆+脚本生成+批量出片
- **数字人**：数字人Skill+本地运行；3D写实+30分钟出片

联动关系：各场景详细部署参考 `企业客户实操手册/`，算法Skill加载参考 `crayfish-safety-monitoring` / `crayfish-shelf-gap-detection` / `digital-human-content`，政企合规参考 `lingxia-platform`。

### 3.3 输出物

- **实施记录**（`references/implementation-log-template.md`）：每步操作+耗时+问题+解决
- 部署清单全部勾选完毕（带照片证据）

### 3.4 确认门

实施完成 + 初步试运行成功 → 进入Phase 4联调测试

---

## Phase 4：联调测试与算法调优

**输出物**：联调测试报告 + 算法调优记录

### 4.1 联调测试3要素

| 要素 | 内容 |
|------|------|
| **功能测试** | 摄像头接入、Skill运行、告警推送、数据回流 |
| **性能测试** | 准确率（召回率>95%）、误报率（<5%）、延迟（<3秒）、并发 |
| **压力测试** | 满负荷运行24小时+、温度监测、断网恢复测试 |

### 4.2 算法调优3-7天

- **样本收集**：正负样本各200-500张（质检类）/100-300个SKU（零售类）
- **标注训练**：手动标注 → 自动训练 → 主动学习
- **阈值调整**：根据客户质量要求平衡召回率vs误报率
- **持续迭代**：每天观察告警数据，每周调优一次

### 4.3 输出物

- **联调测试报告**（`uat-report-template.md`）：3要素测试结果+准确率曲线+遗留问题清单

### 4.4 确认门

测试通过 + 准确率达到客户要求 → 进入Phase 5上线交付

## Phase 6：故障应急响应

**输出物**：故障诊断报告 + 解决方案 + 应急预案更新

### 6.1 应急响应SLA

| 级别 | 场景 | 响应时间 | 解决时间 |
|------|------|---------|---------|
| **P0 紧急** | 业务中断/停产/事故相关 | 30分钟内首响应 | 4小时内解决 |
| **P1 高** | 核心功能失效（如告警全部失效） | 2小时内首响应 | 24小时内解决 |
| **P2 中** | 部分功能异常（如某SKU识别不准） | 4小时内首响应 | 72小时内解决 |
| **P3 低** | 性能优化/小问题 | 24小时内首响应 | 下次巡检解决 |

### 6.2 排错5步法

1. **现象记录**：客户反馈内容、设备状态截图、告警日志
2. **远程诊断**：SSH/远程桌面查看设备状态、运行日志
3. **现场排查**：必要时上门，按"硬件→网络→Skill→数据"顺序排查
4. **根因分析**：5-Why分析，找到根本原因
5. **解决方案**：临时方案+永久方案+预防措施

### 6.3 常见问题分类速查

按"硬件→网络→Skill→数据→对接"顺序排查：
- **硬件类**：过热、掉线、摄像头无画面、电源故障
- **网络类**：断网、带宽不足、IP冲突、VLAN隔离
- **Skill类**：识别不准、告警延迟、Skill崩溃、版本不兼容
- **数据类**：数据丢失、回流出错、存储满、备份失败
- **对接类**：MES/PLC对接失败、企微推送失败、SaaS订阅异常

详见 `references/troubleshooting-guide.md` 按产品分章节的故障排查指南。

### 6.4 输出物

- **故障诊断报告**（`incident-report-template.md`）：5-Why分析+解决方案+预防措施
- **应急响应SOP**（`emergency-response-sop.md`）：分级响应流程

### 6.5 确认门

故障解决 + 客户确认 → 归档到案例库，更新知识库

## Phase 7：长期运维

**输出物**：月度运维报告 + 升级方案 + 客户关系维护

### 7.1 月度巡检5项

- 设备运行状态（CPU/内存/温度/磁盘）
- Skill运行状态（准确率/告警次数/异常率）
- 网络连通性（内外网/带宽/延迟）
- 数据备份（完整性/可恢复性）
- 客户使用反馈（满意度/新需求/问题）

### 7.2 升级迁移触发条件

- Skill版本更新 → 在线热更新
- 算法优化 → 在线推送
- 硬件扩容 → 现场加装+配置
- 模型升级 → 在线热更新
- 硬件迭代 → 现场更换+数据迁移

### 7.3 输出物

- **月度运维报告**（`monthly-ops-report-template.md`）
- **升级方案**（按需，参考 Phase 2 模板）
- **客户关系维护记录**（CRM系统）

### 7.4 确认门

月度报告提交客户 → 进入下一周期

---

## Phase 8：客户反馈闭环

**输出物**：客户反馈报告 + 产品改进建议 + 案例库归档

### 8.1 反馈收集4渠道

| 渠道 | 形式 | 频率 |
|------|------|------|
| 现场反馈 | FDE现场直接收集 | 每次部署/巡检 |
| 客服反馈 | 客户拨打support@594agent.com | 实时 |
| 月度调研 | 客户满意度调研表 | 每月 |
| Agent俱乐部 | 社区反馈+Skill建议 | 持续 |

### 8.2 反馈分类与流转

- **Bug类**（设备/软件故障） → 技术团队，24小时内
- **功能类**（新功能需求） → 产品团队，1周内评估
- **场景类**（新行业/新场景） → 解决方案团队，1周内回复
- **战略类**（生态合作/算网接入） → 商务团队，1周内回复

### 8.3 案例库归档

每个完成的FDE项目（含解决方案+部署过程+ROI数据）应归档为案例，供销售/产品/培训/营销团队复用。

### 8.4 输出物

- **客户反馈报告**（`feedback-report-template.md`）
- **产品改进建议清单**（按优先级排序）
- **案例库文档**（按场景归档）

### 8.5 确认门

反馈提交产品/技术/商务团队 → 纳入需求池

## 修改模式

- **紧急插队**：Phase 6故障应急触发时，暂停当前Phase，先处理故障再回归
- **需求变更**：客户在Phase 1-5提出变更 → 评估影响 → 更新方案 → 确认后继续
- **项目升级**：Lite→Pro或新增场景 → 复用Phase 1-3 + 保留数据 + 重做Phase 4联调

## 关键原则

1. **现场第一**：FDE核心战场是客户现场，50%+时间在现场
2. **业务沉浸**：抵达现场先跟随业务人员走流程
3. **双向闭环**：客户需求→产品团队；产品新能力→客户现场
4. **应急优先**：P0故障30分钟内首响应
5. **长期主义**：从成交到转介绍的全生命周期负责
6. **联动而非重复**：按需调用现有技能获取深度内容
7. **文档标准化**：17类交付物全部使用references/中的模板
