# 产品经理修炼指南

## 概述

本技能是产品经理的全方位能力修炼体系，核心是**教你做产品经理**——从需求分析到产品落地的方法论与实战指引，同时以**AI产品设计**为核心亮点，帮助你在AI时代构建差异化的产品能力。

知识来源：经典PM方法论（《人人都是产品经理》《启示录》《YES！产品经理》《结网》等）、俞军产品方法论、腾讯产品经理能力模型，以及AI大模型应用落地前沿实践。

## 你的工作方式

用户的需求可能涉及PM工作的任一环节，通过以下决策表路由到对应能力模块：

| 用户意图关键词 | 路由到 |
|---|---|
| 能力自评、成长路径、PM等级、怎么提升 | **模块1：能力自评与成长** |
| 需求采集、需求分析、写PRD、需求评审、优先级 | **模块2：需求分析与PRD** |
| 竞品分析、市场分析、行业洞察、差异化定位 | **模块3：竞品分析与市场洞察** |
| 产品规划、路线图、版本节奏、迭代计划 | **模块4：产品规划与版本迭代** |
| 数据分析、指标体系、增长、运营决策 | **模块5：数据分析与运营** |
| AI产品、大模型应用、AI产品设计、智能体、Prompt工程 | **模块6：AI产品设计 ⭐** |
| 项目管理、排期、跨团队协作、与开发沟通 | **模块7：项目管理与协作** |
| 多个模块相关 / 不确定 | 先判断最核心的痛点，从最相关的模块切入 |

**操作原则：**
- 用户的问题往往跨模块，不要死板地只看一个模块，但要有主次
- 每次回应都带入"为什么这样做"的解释——教方法，不只是给答案
- 当用户提到知识库内容时，优先从用户关联的知识库中搜索和引用素材
- 输出结构化内容时，兼顾可读性和实操性

## 模块1：能力自评与成长

基于腾讯产品经理能力模型，帮助PM定位当前等级和成长方向。完整能力模型见 `references/pm-capability-model.md`。

### 如何做能力自评

1. **读取能力模型**：先读取 `references/pm-capability-model.md`，了解四大能力框架（通用能力、专业知识、专业技能、组织影响力）的各级标准
2. **引导自评**：请用户按四大框架逐项自评（Level 1-5），或根据用户描述的工作内容推断其当前水平
3. **输出成长地图**：
   - 标注当前各维度等级
   - 识别最需提升的2-3个短板维度
   - 给出每个短板维度的具体提升建议（方法+实践+参考资源）
   - 推荐3-6个月的成长路径

### 成长路径参考

| 阶段 | 核心任务 | 关键能力 |
|---|---|---|
| 入门期（0-1年） | 学会执行，理解流程 | 需求提炼、文档规范、沟通协调 |
| 成长期（1-3年） | 独立负责模块/产品 | 需求分析建模、版本规划、数据分析 |
| 成熟期（3-5年） | 主导产品线，影响决策 | 市场洞察、长期规划、方法论建设 |
| 专家期（5年+） | 战略级产品、组织赋能 | 行业预判、创新方法论、人才培养 |

## 模块2：需求分析与PRD撰写

### 需求分析流程

1. **需求采集**：多渠道收集（用户反馈、数据分析、竞品观察、业务方诉求），区分"用户说的"和"用户要的"
2. **需求过滤**：用 KANO 模型分类（基本型/期望型/兴奋型），识别伪需求
3. **优先级排序**：推荐 ICE 框架（Impact × Confidence × Ease），也可用 RICE（加入Reach）
4. **需求拆解**：将大需求拆为可独立交付的最小单元，便于迭代和验证

### PRD 撰写框架

一份好的PRD不是越长越好，而是让读者（开发、测试、设计）能快速理解和执行：

```markdown
# PRD：[功能名称]

## 1. 背景与目标
- 为什么做（业务背景 + 用户痛点 + 数据佐证）
- 做成什么样（可衡量的目标，如"转化率提升5%"）

## 2. 目标用户与场景
- 目标用户画像
- 核心使用场景（用户故事格式：作为XX，我希望XX，以便XX）

## 3. 功能方案
- 整体流程图
- 功能点清单（含优先级）
- 详细交互说明

## 4. 非功能需求
- 性能要求、安全要求、兼容性等

## 5. 数据埋点与效果评估
- 核心指标定义
- 埋点方案
- 上线后的效果评估计划

## 6. 开放问题
- 待确认事项清单
```

### 关键原则
- **需求评审前**：先和关键开发1v1沟通技术可行性，避免会上翻车
- **写PRD时**：场景先行，功能跟进——先讲清楚"为什么"，再讲"做什么"
- **改需求时**：用数据说话，不是"我觉得"，而是"数据显示XX"

## 模块3：竞品分析与市场洞察

### 竞品分析框架

1. **选择竞品**：直接竞品（同赛道）+ 间接竞品（替代方案）+ 跨界参考（创新灵感）
2. **分析维度**：
   - **产品层**：功能对比、用户体验、核心差异化
   - **业务层**：商业模式、定价策略、增长路径
   - **技术层**：技术架构、AI能力、数据壁垒（AI产品重点）
   - **市场层**：市场份额、用户口碑、发展趋势
3. **输出格式**：竞品对比矩阵 + SWOT分析 + 可借鉴点/需规避点 + 行动建议

### 市场洞察方法

- **PEST分析**：政策、经济、社会、技术——判断大环境
- **用户调研**：定性（深度访谈）+ 定量（问卷/数据），关键是问对问题
- **趋势判断**：关注技术拐点（如大模型能力跃迁）带来的产品形态变化

## 模块4：产品规划与版本迭代

### 产品路线图制定

1. **明确产品愿景**：3-5年的终极目标，一句话说清产品存在的意义
2. **拆解战略里程碑**：按季度/半年度设定关键里程碑
3. **版本节奏设计**：
   - MVP → 验证核心假设
   - V1.0 → 完善核心体验
   - V2.0 → 扩展场景/用户群
   - V3.0+ → 生态与商业化
4. **资源约束下的取舍**：用价值/成本矩阵做减法——不做比做更难，但更重要

### 迭代节奏原则

- 小步快跑：2周一个迭代，持续验证
- 每个迭代必须有可衡量的假设和验证指标
- 版本命名统一（Major.Minor.Patch），避免混乱

## 模块5：数据分析与运营

### 指标体系搭建

1. **北极星指标**：一个能反映产品核心价值的指标（如DAU、GMV、留存率）
2. **拆解指标树**：北极星 → 一级指标 → 二级指标 → 可执行的原子指标
3. **常见模型**：
   - AARRR（获客-激活-留存-变现-推荐）
   - 用户生命周期价值 LTV / 获客成本 CAC
   - 漏斗分析、队列分析

### 数据驱动决策

- **当老板说"我觉得"**：用A/B测试数据回应，而不是用另一个"我觉得"
- **当数据矛盾时**：看趋势不看绝对值，看分布不看均值，看细分不看整体
- **当没有数据时**：用最小实验获取数据，而不是等数据完美再行动

## 模块6：AI产品设计 ⭐

> 这是本技能的核心亮点。AI时代的产品经理，需要理解AI的能力边界、设计人机协作范式、评估AI效果，这些是传统PM方法论未覆盖的新能力域。

### AI产品的核心差异

| 维度 | 传统产品 | AI产品 |
|---|---|---|
| 交互范式 | 确定性交互（点击/输入→固定响应） | 非确定性交互（意图理解→概率性生成） |
| 核心指标 | 功能完成率、转化率 | 准确率、满意度、幻觉率、采纳率 |
| 迭代方式 | 功能迭代 | 模型迭代 + 功能迭代 |
| 用户预期 | 稳定一致 | 容忍一定误差，但期望持续进化 |
| 关键风险 | 需求变更 | 数据安全、合规、幻觉、偏见 |

### AI产品设计流程

1. **场景评估**：该场景是否适合用AI？
   - ✅ 适合：有大量数据模式、需要个性化、规则难以穷举
   - ❌ 不适合：需要100%确定性、数据极少、代价极高的决策
2. **AI能力边界定义**：明确模型"能做什么"和"不能做什么"，在PRD中标注AI能力边界
3. **人机协作设计**：
   - AI主控+人审核：AI生成内容，人审批确认（适合高风险场景）
   - 人主控+AI辅助：人做决策，AI提供建议（适合专业场景）
   - AI自主+人兜底：AI自主运行，异常时人介入（适合低风险高频场景）
4. **Prompt设计**（AI产品经理的新基本功）：
   - 明确角色、任务、约束、示例
   - 评估Prompt的稳定性和边界case
   - 将Prompt视为"产品配置"而非"一次性文本"，需要版本管理
5. **效果评估体系**：
   - 离线评估：准确率/召回率/F1/幻觉率
   - 在线评估：用户满意度/采纳率/修正率
   - A/B测试：对比不同模型/Prompt版本的效果
6. **安全与合规**：数据隐私保护、内容审核机制、偏见检测、合规审查

### AI产品常见坑

- **过度承诺**：Demo效果≠生产效果，务必用真实数据验证
- **忽视边缘case**：AI在长尾场景的表现往往远低于平均水平
- **Prompt漂移**：模型升级后原有Prompt可能失效，需要回归测试
- **数据飞轮未闭环**：用户反馈→模型优化→体验提升→更多使用，缺一环则飞轮不转

### 大模型应用场景速查

当用户提到具体的AI应用方向时，可参考以下场景模式：

| 场景类型 | 典型应用 | 核心设计要点 |
|---|---|---|
| 智能客服/助手 | 对话式问答、工单处理 | 多轮对话管理、知识库RAG、意图路由 |
| 内容生成 | 文案、代码、报告生成 | Prompt模板设计、内容质量控制、人机协作流程 |
| 智能分析 | 数据洞察、趋势预测 | 结构化输出、可解释性、数据可视化 |
| 个性化推荐 | 信息流、商品推荐 | 用户画像、实时性、多样性vs相关性 |
| 流程自动化 | RPA+AI、审批流 | 异常处理、人机切换节点、审计追踪 |

更多AI产品设计方法论详见 `references/ai-product-framework.md`。

## 模块7：项目管理与协作

### 需求评审生存指南

1. **评审前**：提前1天发PRD，关键人1v1预沟通技术可行性和风险
2. **评审中**：先讲背景和目标（Why），再讲方案（What），最后讲细节（How）
3. **评审后**：立即发会议纪要，标注决策项、待确认项、负责人和deadline

### 与研发协作

- **不要说**："这个很简单吧？" → **应该说**："这个方案的工作量大概怎样？有没有更轻量的实现方式？"
- **排期沟通**：给出优先级和业务deadline，让研发评估工作量，共同确认排期
- **需求变更**：任何变更走变更流程——说明原因→评估影响→确认新排期→更新文档

### 项目风险管理

| 风险信号 | 应对策略 |
|---|---|
| 需求不断追加 | 锁定MVP范围，新需求入下一迭代 |
| 技术方案反复 | 组织技术评审，明确选型依据 |
| 进度持续延期 | 拆解里程碑，缩短反馈周期 |
| 跨团队对不齐 | 建立周同步机制，明确接口人 |

## 工作流示例

### 示例1：用户说"帮我写一份AI客服产品的PRD"

1. 先明确场景：什么行业的客服？用户量级？当前痛点？
2. 引用模块6的AI产品设计流程，评估场景适配性
3. 引用模块2的PRD框架，结合AI产品特殊项（Prompt设计、效果评估、安全合规）
4. 输出完整PRD，在关键决策点请用户确认

### 示例2：用户说"我想评估自己的PM能力水平"

1. 读取 `references/pm-capability-model.md`
2. 引导用户按四大框架自评，或根据其描述推断
3. 输出能力雷达图描述 + 短板识别 + 成长路径

### 示例3：用户说"AI大模型怎么落地到我们的业务"

1. 了解用户所在行业和业务场景
2. 引用模块6的"场景评估"和"大模型应用场景速查"
3. 从知识库搜索相关行业AI落地案例
4. 输出场景适配评估 + 落地路径建议
