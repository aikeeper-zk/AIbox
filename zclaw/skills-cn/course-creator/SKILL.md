# Course Creator · 课程生产工作流

## 概述

课程生产工作流将任何主题的系列课程创建拆解为四个标准阶段：**总纲设计 → 内容生产 → 归档入库 → 推广排版**。从用户给一个主题开始，到产出完整的课时 MD 文件并归档到知识库，全流程可重复、可扩展。

始终使用 references/ 中的模板文件来确保输出的一致性。

## 决策入口

在进入流程前，先判断用户意图属于哪种场景：

| 场景 | 判断线索 | 走哪个流程 |
|:----|---------|-----------|
| 🆕 **从头做一套新课** | "帮我做个XX课""搞个XX系列课""把XX做成课时" | 走完整 4 个 Phase |
| ➕ **扩充已有课程** | "在XX课程基础上再加几课""给XX课补几节" | 走 Phase 2→3→4（跳过总纲设计，基于原有结构扩充） |
| ✏️ **修改已有课时** | "把第X课改一下""XX那课的内容我想调" | 走**修改模式**（见下方说明） |

如果用户意图不明确，直接问清楚再进入对应流程。

## 工作方式

按照以下阶段依次推进。不同入口场景对应不同流程。每个阶段完成后需要用户确认或提供下一步信息（确认门），再进入下一阶段。

---

## Phase 1：总纲设计

**输出物**：用户确认的总纲草案 MD 文件

**流程：**

### 1.1 需求确认
- 明确课程主题（什么领域的课）
- 确定课时数（默认 10-20 课时）
- 确定目标受众（给谁看的）
- 确定输出风格（专业深度型 / 通俗普及型 / 实操导向型）

### 1.2 模块框架设计

设计 4-5 个递进模块。通用递进逻辑参考：

| 位置 | 定位 | 说明 |
|:----:|------|------|
| 模块一 | 认知筑基 | 建立底层认知，对齐基本概念 |
| 模块二 | 能力/技术深挖 | 深入核心知识或技能 |
| 模块三 | 场景实践 | 真实场景下的应用与实操 |
| 模块四 | 业务/生态拓展 | 连接更广阔的领域 |
| 模块五 | 趋势展望 | 前沿展望与未来方向 |

按主题灵活适配模块名，不局限于此。各领域模块命名参考：

| 领域 | 推荐模块顺序 |
|:----|-------------|
| AI/科技 | 认知篇→技术篇→能力篇→工程篇→生态篇 |
| 财经/投资 | 认知篇→工具篇→策略篇→实战篇→进阶篇 |
| 商业/创业 | 认知篇→方法篇→案例篇→实操篇→趋势篇 |
| 人文/历史 | 起源篇→发展篇→高峰篇→思辨篇→启示篇 |
| 生活/技能 | 入门篇→基础篇→进阶篇→高手篇→大师篇 |
| 教育/心理 | 认知篇→方法篇→实践篇→案例篇→延伸篇 |

### 1.3 课时编写
每课填写：**序号 + 标题 + 核心要点（一句话说清学什么）**

### 1.4 确认门
将总纲草案输出为 MD 文件提交用户确认。用户确认后进入 Phase 2。

**模板**：`references/course-outline-template.md`

## Phase 2：内容生产

**输出物**：各课时独立 MD 文件

### 2.1 目录结构

```
课程名/
├── 01_模块文件夹/
│   ├── 01_课时标题.md
│   └── 02_课时标题.md
├── 02_模块文件夹/
│   ├── ...
│   └── ...
├── 03_模块文件夹/
├── 04_模块文件夹/
└── 05_模块文件夹/
```

- 模块文件夹命名：`序号_模块名`（如 `01_认知篇`）
- 课时文件命名：`序号_标题.md`（如 `01_从BERT到GPT：大模型演进简史.md`）
- 输出到 `/sandbox/workspace/outputs/` 下

### 2.2 子代理并行生产

按模块拆分任务，每个模块启动一个子代理（`subagent_spawn`，type=general，model=heavy）独立产出。

**每个子代理的 task 必须包含：**
- 输出的目标目录
- 需要完成的文件列表（文件名 + 核心要点 + 搜索方向）
- 每课的结构规范
- 写作要求

### 2.3 每课标准结构

```markdown
# 第X课：标题

## 概述
（300-500字，介绍本课学什么、为什么重要）

## 核心知识点
（分3-5个知识点，每个包括定义、原理、例子）

### 知识点1：xxx
...

## 案例与实践
（至少1个具体案例）

## 关键概念总结
（3-5个术语）

## 延伸阅读
（2-3条资源）
```

### 2.4 质量标准

- 每课正文 1000-1500 字
- 每课搜索至少 2-3 个中文来源，综合撰写
- 每个知识点含定义、原理、例子三层
- 至少 1 个真实案例
- 主题相关术语表

**模板**：`references/lesson-template.md`、`references/subagent-task-template.md`

### 2.5 确认门
验证所有课时文件是否完整。确认后进入 Phase 3。

## 修改模式（适用于扩充或修改已有课程）

当用户说"再加几课""把第X课改一下"时，从主流程切换到修改模式。不需要重走全部 Phase。

### 扩充流程（加新课）
1. 确认扩什么方向、加几课（1-5课）
2. 直接进入 Phase 2 子代理产出（不重新建目录，沿用原课程文件夹）
3. 产出后直接上传到对应模块文件夹 + 打标签
4. 不需要总纲公众号版

### 修改流程（改已有内容）
1. 定位目标文件（知识库对应文件夹内的具体课时）
2. 读取原文件，理解现有结构
3. 按用户要求修改（增/删/改知识点、换案例、调结构）
4. 重新上传覆盖原文件（同一文件夹，同一文件名）
5. 通知用户修改完成

---

## Phase 3：归档入库

**输出物**：知识库归档 + 标签体系

### 3.1 知识库文件夹创建

```
知识库根目录
├── 📁 [课程名]（主文件夹）
│   ├── 📁 01_模块一
│   ├── 📁 02_模块二
│   ├── 📁 03_模块三
│   ├── 📁 04_模块四
│   ├── 📁 05_模块五
│   └── 📄 [课程名]总纲_草案.md（放根目录）
```

使用 API `/openapi/wiki/v1/create_folder` 创建文件夹，先建主文件夹（不传 folder_id），再建子文件夹（folder_id=主文件夹ID）。

### 3.2 批量上传

使用 `/sandbox/workspace/skills/ima-knowledge/scripts/upload_file.py` 逐文件上传：

```bash
python3 .../upload_file.py \
  --file-path <md文件> \
  --knowledge-base-id <kb_id> \
  --folder-id <目标文件夹ID>
```

### 3.3 打标签

每个文件打双层标签：
- **模块标签**：如"认知篇""能力篇""生态篇"（按模块名）
- **课程标签**：如"AI大模型课程""财商课"（整个课程一个统一标签）

使用 API `/openapi/wiki/v1/tag_add`。

### 3.4 确认门
验证所有文件是否成功上传并标记。确认后进入 Phase 4。

---

## Phase 4：推广排版（可选）

**输出物**：公众号富文本 HTML

### 4.1 配色确认
用户指定配色，或从主题推断（参考 wechat-rich-text skill 的配色方案）。

### 4.2 生成 HTML
将总纲转换为公众号兼容的富文本 HTML（纯内联样式，只使用 `<section>` 和 `<p>`）。

推荐结构：
- 封面区（渐变背景 + 标题 + 副标题）
- 课程设计逻辑表
- 各模块章节（标题条 + 数据表格）
- 适用人群
- 品牌尾条

### 4.3 交付
- 上传 HTML 到知识库对应主文件夹
- 提供下载链接给用户
- 可选：更新知识库简介（description）和推荐问题（recommended_questions）

## 工作流示例

### 示例 1：AI/科技类课程
用户说："帮我做一个关于AI Agent的课程，20课时"

→ Phase 1：设计总纲（AI Agent→认知/能力/协同/生态/前沿）
→ Phase 2：5个子代理各4课，按标准结构产出
→ Phase 3：建"AI Agent课程"文件夹 + 上传 + 标签"认知篇""AI Agent课程"
→ Phase 4：总纲公众号富文本（科技蓝配色）

### 示例 2：泛领域课程
用户说："我想搞一个财商课，10课时"

→ Phase 1：设计总纲（财商→认知/工具/策略/实战/进阶）
→ Phase 2：搜索理财资料，产出资深内容（每课1500字+真实案例）
→ Phase 3：建"财商课"文件夹 + 上传 + 标签"工具篇""财商课"
→ Phase 4：总纲公众号富文本（金色/财富配色）

### 示例 3：教育/人文类课程
用户说："帮我做个世界史入门课，15课时"

→ 决策入口：🆕 从头做一套新课
→ Phase 1：设计总纲（世界史→基础篇→文明篇→近现代篇→思辨篇→拓展篇）
→ Phase 2：按文明/地区拆分模块，子代理并行产出
→ Phase 3：建"世界史入门"文件夹 + 上传 + 标签"基础篇""世界史入门"
→ Phase 4：总纲公众号富文本（教育绿配色）

## 关键原则

1. **领域无关性**——流程适用于任何主题，不局限于科技/AI
2. **模板驱动**——总纲模板 + 课时模板 + 子代理任务模板，保证一致性
3. **并行生产**——按模块拆分到子代理，大幅缩短生产周期
4. **确认门**——每阶段结束有用户确认点，避免方向偏移
5. **标签体系**——双层标签（模块+课程），检索极快
